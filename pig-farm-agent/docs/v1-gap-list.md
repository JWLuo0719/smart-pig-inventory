## 6. 本轮（V1 收尾第三轮）完成内容

1. **最小 Web 看板收尾**
   - 事件流新增总览卡（筛选事件数、未关闭、高中风险未关闭、最近事件时间）；
   - 日报页新增"模型升级门槛（回放基线）"面板，直读 `/model/replay`；
   - 新增可选写保护令牌（`PIG_AGENT_API_TOKEN`）与看板令牌设置入口，401 自动提示重填；
   - 新增 `tools/check_dashboard_js.mjs`：内联脚本语法 + 看板引用路由与 `server.py` 一致性检查。
2. **目录轮询输入收尾**
   - 来源可追溯：`state.source_device` 与文件名/侧车时间戳解析；
   - 记录稳定才处理（`settle_scans`），避免读到摄像头正在写入的半张图；
   - 侧车 JSON 随图片一起归档；`--once`/`--device`/`--interval`/`--defer-scans` CLI；
   - `build_poller` 统一服务端与独立进程的构建路径。
3. **回放测试框架收尾**
   - 由"仅检测器"升级为**全链路**回放（检测 → 状态 → 风险 → 证据 → 事件），
     对比候选数/计数/质量状态/**风险等级与代码**/端到端耗时；
   - 固定夹具 11 张 + 基线 `baseline.json`（含夹具指纹），生成脚本自检风险通路覆盖；
   - `MockDetector` 种子改为 `request_id + 栏舍 + 图片指纹`（不含完整路径），
     回放结果跨机器/跨数据目录可复现，基线可迁移；
   - CLI 支持 `--mode`、`--tolerance`、`--max-ms`、`--allow-risk-change`、`--print`。

## 7. 后续优先事项

1. **先定 Agent 与 App 的关系**（见 `docs/app-integration-contract.md` §1）：
   推荐把 Agent 做成 App 推理 Provider 契约后面的计数服务，而不是复制 Spring 的
   身份/主数据/对象存储/复核谱系；
2. 用校准后的 ONNX 制品重建真实回放基线，并记录 MAE 与单张耗时（目标 ≤ 3 秒）。
3. 边缘主机上跑 7 天连续运行：轮询目录持续投图，统计事件写入成功率、重复率与内存曲线。
4. 与 `smart-pig-inventory` 真机联调：用 `tools/run_app_replay.py` 对真实服务跑 6 个弱网场景。
5. 试点现场脱敏图片替换回放夹具，把现场角度/光照纳入门槛。
