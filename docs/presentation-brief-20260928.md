## 一、30 秒开场总览

项目是一个**弱网可用的猪场盘点 App**：现场人员在栏舍拍照（单图或左中右三图），断网也能存，出栏舍自动续传到服务器；AI 给出**候选头数**，复核员人工确认后形成**不可篡改的日盘点记录**，管理员出日报、综合平均和 PDF/Excel 报表。

当前进展：

- **核心业务闭环全部打通并自动化验证**：Spring 103 项、推理 88 项、App 59 项、管理端 24 项测试全过。
- **签名 Release APK** 已在真机（Redmi K60）迭代到 **v19**，非视频功能已通过用户人工测试。
- **AI 保持"研究模式"**：能出候选数但强制人工复核——这是治理设计，不是缺陷。

## 二、功能清单（用户看到什么 → 背后怎么实现）

### 1. 移动端 App（Flutter / Android）

#### ① 离线采集与恢复（看家本领）

- **看到**：选栏舍 → 拍照（单图/左中右三图）→ 显示"已保存，待上传"；杀 App、重启手机，照片/ROI/排队状态全在；断网时不显示任何头数。
- **实现**：照片先复制进 App 私有目录才建草稿（防图库清理丢证据）；本地用 Drift(SQLite) 持久化草稿、媒体、上传队列；每张图算 SHA-256 存库。
- **证据**：realme 验证"拍三张 → 强制停止 → 重启完整恢复"；v16/v18 在 K60 验证重启后队列自动续传。

#### ② 弱网断点续传

- **看到**：断网暂停、联网自动续；传一半杀进程，重启只传剩余文件，不重复传。
- **实现**：上传四步 **创建包 → 逐张传 Blob → 提交清单 Manifest → Commit**，每步带**幂等键**（服务器认键不认次数）；每张 Blob 独立状态 + 租约 + 指数退避；WorkManager 后台调度；本地原图等服务器 Commit 成功才标 synced。
- **证据**：v18 真机一个卡住的上传包，没点任何按钮，重启后自动走完四步到服务器（"已提交、待复核 21"）。

#### ③ 五入口真实数据（首页/任务/盘点/图库/我的）

- **看到**：首页今日任务进度（如 0/2）、待上传数、异常提醒——全部来自服务器或本地库，**无写死演示数据**。
- **实现**：Repository 模式，读激活组织的 API + Drift 本地缓存；离线只显示本机可证实的状态。
- **证据**：v16 真机 `/me` 与任务接口 200，首页显示 2 个真实任务。

#### ④ ROI 标注与邻栏排除

- **看到**：拍完照在图上拖矩形框出"不计入本栏的区域"（隔壁栏、料槽），可删可调。
- **实现**：手机端画框存归一化坐标 → 随上传清单传服务器 → 推理按"检测框中心点在有效区内才计数，落排除区/包含比例不够就剔除"过滤。
- **状态**：代码 + 7 项界面测试完成；真机手势操作待人工验收。

#### ⑤ 复核确认入口

- **看到**：待复核会话显示 AI 候选框叠加、候选头数、模型版本、失败原因；确认后"已确认并锁定 N 头"。
- **证据**：真机完整闭环——候选 19 → 人工确认 24 → 媒体锁定。

#### ⑥ 视频证据（采集/上传/播放已做，自动计数未开）

- 能录 MP4、上传、App 内播放，进人工确认流程；**视频不自动出数**。

### 2. 管理端（Next.js）

| 功能 | 用户看到什么 | 关键实现点 |
|---|---|---|
| 现场态势 | 当日各栏任务、会话状态、候选框预览 | 同源代理（白名单方法/路径），令牌只存内存 |
| 人工确认/更正 | 确认数量；**确认错了不能改，只能"更正"** | 更正生成新版本 v2，旧版 v1 变 `superseded` 永久保留；DB 唯一约束保证同栏同日只有一个当前版本 |
| 媒体审核 | 近重复告警、带理由处理 | 感知哈希 dHash 汉明距离 ≤8 建告警，**只标记不自动删** |
| 失败任务重试 | 看失败码，带理由重试 | 重试**新建**任务挂同一谱系，原失败任务不覆盖；同理由重放只产生一个后继 |
| 报表导出 | 按日期导 PDF/Excel | 两格式读**同一份确认快照**；366 天/1 万条上限；中文字体嵌入；防公式注入 |
| 面板状态 | 加载中/无权限/失败/空列表**四种状态分开** | 失败绝不显示"0 条"冒充空 |

### 3. 后端与 AI 链路（Spring + Python）

#### ⑦ AI 推理闭环（Commit → 候选 → 人工确认）

- **链路**：照片 Commit → 事务 Outbox 派发推理任务 → Celery Worker 调模型服务 → 带服务密钥的回调写回候选框 → 会话 `review_required` → **人工确认才进报表**。
- **出数时**：模型返回检测框 → 服务端二次校验（模型身份 checksum、框合法性、ROI 过滤）→ 数框形成候选值。
- **不可用时**：Runner 没起/超时/身份不符 → 空数量 + 明确失败原因 → 照样转人工，照片不丢（fail-closed）。
- **证据**：09-12 真机单图闭环——上传→推理→回调→人工确认→锁图→审计事件一次通过。

#### ⑧ 两级防重

- 同组织**完全相同**（SHA-256）→ 直接拒收，返回原图引用；
- **长得像**（感知哈希 ≤8）→ 只生成告警进复核，绝不自动删。

#### ⑨ 审计与权限

- 删图、解锁、人工改数、模型重试全部留不可变审计（操作人/原因/前后值/时间）；
- 四角色 RBAC + 组织隔离，越权返回 404（不泄露对方存在）；确认后图普通删除 409，管理员覆盖须填原因且只能软删除。

#### ⑩ 智能研判面板（App 首页）

- **看到**：当日概览 + 建议："XX 栏待复核（候选比上次少 15%）""XX 栏已 3 天没采集""今日已确认 2/5 栏"。
- **实现**：**纯规则引擎，不调大模型**——近 7 日确认数中位数当基线，偏离超 20% 提示；只读、离线可用、每条带数据出处。

### 4. 工程与运维（一句带过）

- 数据库迁移 Flyway（V1–V13+），只增不改；
- 备份恢复：停写冷快照 + 全新卷恢复演练通过（同证据 SHA-256、锁定图删除 409 验过）；
- 可观测性：上传各阶段指标 + Prometheus + 6 组告警规则测试；
- 局域网真机环境：自建 CA 签 `pig-inventory.local` TLS + mDNS，手机扫码即连，不绕过证书校验。

## 四、"怎么实现的"高概率问答

**Q：断网拍照，网恢复后怎么保证不传丢、不传重？**
本地 SQLite 存草稿和每张图的上传状态；上传分四步，每步带幂等键，服务器认键不认请求次数；每张图单独传单独校验哈希，断了只续传没成功的；最后 Commit 成功才在本地标"已同步"。

**Q：AI 数的头数能直接进报表吗？**
不能，这是产品设计。AI 出的是"候选"，报表只读"人工确认数"。真机对照过一次：AI 候选 19、人工 24，差 5 头——确认权必须在人手里。

**Q：服务器怎么知道照片没被篡改/传错？**
每张图有 SHA-256；Manifest 阶段服务器校验哈希、栏舍、方向、权限；推理结果回来还要过模型身份（checksum）和框合法性校验，对不上就拒绝并转人工。

**Q：确认过的数字发现错了怎么办？**
不允许直接改。发起"更正"→ 生成新版本 v2，旧版标 superseded 永久保留，证据图仍锁定，谁改的、为什么改全部进审计；数据库唯一约束保证同栏同日只有一个生效版本。

**Q：重复照片（同一批猪拍了两张很像的）怎么处理？**
两级：哈希完全相同 → 直接拒收；哈希不同但长得很像（感知哈希距离 ≤8）→ 生成告警让复核员判断，系统绝不自动删。

**Q：为什么 App 有时候就是不给数？**
模型没启动、超时或校验不过时，系统**故意**返回空数量 + 失败原因，转人工数——宁可不出数也不出假数（fail-closed）。照片和证据全程不丢。

**Q：首页那些"建议"是 AI 吗？**
是规则不是大模型：近 7 日确认数中位数当基线，今天偏离超 20% 就提示"数量异常，请核实"。不联网也能用，每条建议都能追溯到具体数据。

**Q：模型什么时候能自动入账？**
需同时满足：许可证准入、金标回归通过、阈值校准、运营负责人批准。当前 `MODEL_APPROVED=false`，发布签名 ≠ 模型批准，两者分开记录。

## 五、演示与口径建议

1. **演示选链**（最稳顺序）：拍照（或断网拍照）→ 恢复网络自动上传 → 管理端看到候选 → 人工确认 → 报表出现该条。
   - ⚠️ 当前局域网栈存在 Runner 端口冲突（9000 端口被 MinIO 占用，尚未修复），**AI 候选环节演示前需先恢复**；时间紧就只演示"上传 → 人工确认 → 报表"，不依赖模型。
2. **主动交代边界**：讲完功能先自己说清三件事——模型没批准、视频自动计数没开、正式部署没做；这些是设计决策和外部依赖，别等被问才解释。
3. **分开记录的四件事**（不可互相替代）：APK 构建、真机联通、真实猪只验收、模型批准。
