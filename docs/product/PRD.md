# 智慧猪场场主 App 综合 PRD

版本：0.2（路线 B+ 架构基线）  
状态：架构基线已确认，P0 实现中  
日期：2026-08-20

## 1. 产品目标

为弱网猪场提供可离线采集、可恢复上传、可审计确认的栏舍级猪只盘点工具。系统把图片、视频和未来 Agent/YOLO 推理视为证据处理链路，而不是不可解释的即时数字生成器。

首版成功标准：现场人员在断网条件下完成单图或左/中/右三图采集，离开栏舍后自动续传，服务器完成真实推理或进入人工复核，管理员确认后形成不可随意删除的日盘点证据和跨日综合结果。

## 2. 用户与职责

| 角色 | 核心任务 | 权限边界 |
|---|---|---|
| 现场盘点员 | 选栏、拍摄、查看队列和结果 | 只能访问所属组织；不能删除锁定媒体 |
| 复核员 | 查看疑似重复、质量告警和计数结果 | 可确认或提出重拍；不能维护组织权限 |
| 猪场管理员 | 任务、人员、栏舍、报表和更正 | 覆盖操作必须填写原因并留审计 |
| 系统管理员 | 模型、同步、失败任务和系统配置 | 不替代业务复核，不直接修改原始证据 |

## 3. 核心业务流程

### 3.1 主数据

1. 管理员维护猪场组织、栋舍和栏舍编码、名称、启用状态。
2. 金蝶通过 `ErpOrganizationProvider` 同步；无正式文档时只能使用 Mock 和人工维护。
3. App 按 `sync_version` 增量缓存主数据，离线时仍可选择最近同步的栏舍。

### 3.2 现场采集

1. 先选择栏舍，再选择单图或左/中/右模式。
2. 每张图片必须有方向、采集时间、SHA-256、原始尺寸、EXIF 和可选 ROI。
3. 原图复制到 App 持久目录后才建立草稿；图库临时 URI 不能作为长期证据路径。
4. 三图模式必须集齐 left、center、right，作为同一 `CaptureSet` 提交。
5. 无网络时显示“已保存，待上传”，不得显示推测数量。

### 3.3 弱网上传

1. 客户端 UUID 和幂等键创建或恢复上传包。
2. 每个 Blob 独立上传并校验大小、SHA-256，可安全重复。
3. Manifest 校验组织、栏舍、方向、ROI、引用和权限。
4. Commit 只执行一次；重复 Commit 返回原任务。
5. 本地原图必须保留到服务器确认 Commit 成功。

### 3.4 推理和复核

1. Commit 后创建持久 `InferenceJob`。
2. Provider 输出统一检测框、置信度、告警、模型版本、适配器版本和耗时。
3. ROI 默认以检测框中心点是否落入有效区判断。
4. 单图可直接产生候选数量；低质量、无模型或近重复进入人工复核。
5. 三视图在跨图去重算法验收前不得简单相加，统一进入人工确认。

### 3.5 确认、锁定和报表

1. 复核员确认日盘点数量，可记录人工修正值和原因。
2. 结果确认后媒体锁定；普通删除返回冲突。
3. 管理员覆盖只能软删除，必须记录操作者、原因、时间、前后值。
4. 综合盘点对参与日期内已确认日盘点取算术平均；展示四舍五入数量，同时保留原始均值和样本日期。

## 4. 功能范围

### P0 首次现场试用

- 登录、令牌刷新和组织隔离。
- 组织/栋舍/栏舍同步与离线选择。
- 单图和左/中/右采集、图库导入、ROI、草稿恢复。
- 本地图库、SHA-256、Outbox、自动与手动续传。
- 幂等上传、对象存储、缩略图、精确重复阻断。
- Mock/Unavailable 推理、人工复核、结果确认和媒体锁定。
- 日盘点、跨日综合盘点、审计日志。
- 管理端组织、任务、媒体审核、报表、模型状态、失败任务。

### P1 正式试点

- 真实 YOLOv13 单图 Provider 和金标回归。
- 金蝶正式 Provider。
- 近重复审核辅助、PDF/Excel 导出、失败任务重试。
- 设备推送和更细 RBAC。

### P2 研究验证

- 多视角跨图去重、视频抽帧/跟踪、端侧推理、模型热更新、Agent 策略编排。
- 死猪上报：不属于 V1；后续按独立业务域评估并接入。

## 5. 页面框架

移动端五个一级入口：`首页 / 任务 / 盘点 / 图库 / 我的`。盘点为中心主操作，但不使用遮挡内容的悬浮大按钮。

- 登录：账号、密码、服务器环境和离线说明。
- 首页：今日任务、最近栏舍、待上传数量、异常提醒、快速继续。
- 任务：按状态和日期筛选，进入栋舍/栏舍进度。
- 盘点：栏舍门牌、采集模式、方向步骤、ROI、草稿确认。
- 图库：栏舍/日期筛选、上传/推理/锁定状态、详情和允许的删除操作。
- 我的：组织、同步时间、存储占用、网络策略、日志和退出。

管理端一级入口：`现场态势 / 任务 / 媒体审核 / 组织栏舍 / 盘点报表 / 模型与同步 / 审计`。

## 6. 数据口径

- “AI 数量”是指定模型版本和 ROI 规则得到的候选值。
- “确认数量”是报表唯一有效值。
- 日盘点同栏舍同业务日期可有多次 Session，但只能有一个最终确认版本；更正产生新版本和审计，不覆盖历史证据。
- 综合平均只包含确认状态，不包含草稿、处理中、需复核或失败记录。

## 7. 风险与开放问题

- 遮挡、多视角、视频和端侧精度未验证，不写入上线承诺。
- 学长系统只作为行为和视觉信息结构参考，不复制其代码或资产。
- 产品名称确认为“智慧猪场场主”；初版 Logo 为可替换的原创临时资产，尚未做商标检索或注册。
- 死猪上报明确不进入 V1；金蝶字段、试点猪场、低端 Android 实测机和边缘服务器配置仍待确认。
- 主流验收机确定为 realme GT 7 Pro；它适合验证 Android 15、120Hz 高刷屏与高端相机路径，但不能替代低端机弱性能/低存储测试。
