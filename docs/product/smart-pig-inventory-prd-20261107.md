## 1. 文档目的与阅读规则

本文定义产品要解决的问题、业务规则、功能需求、权限边界、验收标准和后续范围。

需求状态分为：

- **已实现**：当前源码、自动测试或试用环境已经有对应实现。
- **试用可用**：已部署，但仍需要真实猪场或真实设备验收。
- **规划中**：需求已确认，但当前版本没有交付，不得在产品界面中伪装成可用功能。
- **外部依赖**：需要金蝶接口、真实模型、现场数据或其他外部条件。

“部分实现”表示同一需求中只有部分操作或展示具备；“未启用”表示存在实现或研究入口，但当前运行环境未开放。实现状态截至文档日期，不能替代部署、真机和模型验收。优先级定义：P0 为盘点闭环与数据安全的必要需求；P1 为现场效率及管理增强；P2 为独立验证后引入的扩展能力。

本文作为当前需求描述入口，与 [既有 PRD](PRD.md)、[验收标准](acceptance-criteria.md)、[非功能需求](non-functional-requirements.md)共同使用。HTTP 字段和方法以 [OpenAPI 合同](../../contracts/openapi.yaml)为准。待决事项不视为批准变更。

当前版本以“联网尽快返回候选结果、断网先保存、联网后继续处理”为原则。断网期间不要求手机端自动计数。

## 2. 产品背景与问题定义

猪场现场存在以下实际问题：

1. 猪场、栋舍和栏舍数量多，人工记录容易发生栏舍归属错误。
2. 栏舍网络不稳定，拍摄后不能保证立即上传。
3. 单张照片可能拍不完整，料槽、遮挡和邻栏入镜会造成漏计或重复计数。
4. 同一栏舍可能需要多张照片，简单相加会把同一头猪重复计算。
5. 照片上传后需要按栏舍、日期查询；确认后的证据不能被普通用户删除。
6. AI 检测结果只能作为候选，最终数量必须由人员核对。
7. 月末可能连续几天盘点，需要保留每日记录，并提供可解释的周期参考。
8. 后续需要接入金蝶 ERP、更多视觉模型和多模态智能体，但扩展不能破坏业务数据和审计规则。

## 3. 产品定位

智慧猪场场主是一套以“栏舍”为最小业务单元的猪只盘点系统。

系统由四部分组成：

- **移动作业端**：选择栏舍、拍照或导入、离线保存、上传和复核。
- **Web 管理端**：管理主数据、查看任务、审核证据、维护报表和审计。
- **业务服务**：管理组织、权限、上传、盘点记录、锁定、版本和审计。
- **推理与智能体服务**：提供检测候选、失败信息和只读业务解释。

产品的权威事实来自业务服务。AI 只提供候选和证据，智能体只在授权范围内查询和解释，不能绕过确认、权限、锁定和审计规则。

### 3.1 使用场景

| 场景 | 触发条件 | 用户期望 | 系统产出 |
|---|---|---|---|
| 日常逐栏盘点 | 现场人员进入栋舍 | 快速找到栏舍并记录 | 栏舍、日期明确的采集组 |
| 弱网集中补传 | 栏舍内无法稳定上传 | 先作业，网络好时处理 | 原上传包续传与处理状态 |
| 遮挡和邻栏复核 | 一张照片不足或边界不清 | 查看证据并补拍或核对 | 人工确认值及复核依据 |
| 月末多日盘点 | 连续多天核对存栏 | 查询每日明细及周期参考 | 有参与日期的均值；完整批次为规划 |
| 管理更正 | 确认后发现数量错误 | 纠正当前值并保留责任记录 | 新确认版本和审计 |
| 智能查询 | 用户询问状态或历史 | 在同一组织范围得到有来源的解释 | 授权事实和来源入口；问答启用后可用 |

## 4. 产品目标与非目标

### 4.1 V0.2 目标

- 按猪场、栋舍、栏舍组织现场盘点。
- 支持手机拍照、相册导入和本机证据保存。
- 在联网时上传并获得检测框和 AI 候选。
- 断网时保存栏舍、日期和原图，联网后继续上传。
- 支持人工复核、确认、锁定证据和形成栏舍日报。
- 支持按栏舍、日期查询服务器证据。
- 保证组织隔离、操作权限、幂等上传和审计记录。
- 保持未来接入 ERP、视频、多视角模型和智能体的扩展边界。

### 4.2 当前非目标

- 断网时在手机端自动计算正式数量。
- 将 AI 候选自动写入正式报表。
- 未经过验证的三图跨图去重或视频自动计数。
- 金蝶 ERP 的真实生产同步。
- 通过自然语言直接确认数量、删除证据或修改主数据。
- 根据数量变化自动判断死亡、销售、疾病或转栏原因。

## 7. 业务规则

### 7.1 栏舍归属规则

- 每张照片或视频必须关联一个组织、栋舍、栏舍和业务日期，或者处于“待归属”状态。
- 文件名、拍摄顺序和 EXIF 只能用于提示，不能自动作为最终栏舍事实。
- 未完成归属的素材不能进入正式检测、确认或报表。
- 栏舍编码只在所属组织或栋舍范围内唯一，不能把“03栏”当作全局唯一身份。

当前 App 新建盘点按设备当天生成业务日期，历史查询可选择日期；任意指定采集业务日期不作为现有操作承诺。跨时区或跨午夜作业的统一日期策略需按第 13 节确定。

### 7.2 证据和去重规则

- 同一组织内相同 SHA-256 的文件只能形成一条有效证据。
- 跨栏舍重复提交也必须被拦截，并提示有权限查看的原记录。
- 感知相似只能形成复核告警，不能自动删除原图。
- 不同照片拍到同一头猪属于跨图目标关联问题，不能用文件哈希解决。
- 已被确认结果引用的媒体必须锁定；普通用户不能删除。
- 普通错图删除为软删除；相关会话不能继续确认，需要重新采集。已删除原文件的指纹仍然保留并阻断重复提交，不能通过删除解除跨栏重复限制。
- 管理员覆盖删除锁定媒体与更正盘点数量是两个独立操作；前者不自动改数，后者生成新确认版本。

### 7.3 候选和确认规则

- AI 候选数量、人工确认数量和未知状态必须分别展示。
- 候选数量不进入正式日报、综合报表或正式合计。
- 复核员调整数量时应填写原因；未知候选确认时必须填写依据。
- 合法的人工确认 0 头必须和“未知”区分。
- 确认后修改不能覆盖历史记录，必须创建新版本并保留原证据引用。
- 确认数量必须为非负整数；修正、未知候选确认及更正依据为 8～500 个字符。
- 同栏同日已有确认结果后，不得再把另一采集会话确认为第二条有效结果；需要修改时使用审计更正流程。过时的未复核会话按规则归档并保留证据。

### 7.4 多视角规则

- 左、中、右照片属于同一采集组。
- 未经过跨图去重模型和现场验收前，不得直接把三张照片的候选数量相加。
- 料槽遮挡应优先提示换角度或补拍，不能把整个料槽区域一概排除。
- 邻栏入镜、边界猪和完全不可见区域必须进入人工复核或补拍流程。

### 7.5 多日盘点规则

- 每个栏舍每天可以产生多次采集，但只能有一个当前有效的确认版本。
- 周期平均只使用已确认的每日数量。
- 报表必须显示参与日期、缺失日期和覆盖率。
- 调栏、销售、死亡等导致猪群变化时，平均值只能作为参考，不能自动代表目标日存栏。

| AGT-002 | 查询当日栏舍概览 | P1 | 只读工具已实现，自然语言问答未启用 |
| AGT-003 | 查询单栏历史 | P1 | 只读工具已实现，自然语言问答未启用 |
| AGT-004 | 工具调用绑定组织和角色 | P0 | 已实现 |
| AGT-005 | 事实、解释和证据入口分离 | P1 | 已实现 |
| AGT-006 | 通过自然语言确认、改数或删除 | P2 | 禁止直接开放 |

### 8.8 详细交互和异常约束

| 模块 | 前置条件与输入 | 正常行为和输出 | 异常约束 |
|---|---|---|---|
| 主数据 | 管理权限；编码≤64、名称≤128、原因≤500字符，均非空；当前版本号 | 保存组织/栋/栏的稳定身份和审计；手机同步后生效 | 重码、旧版本拒绝；禁止直接移动父级；停用父级前须先停用子级 |
| 图片采集 | 已缓存的有效栏舍；单图或左中右模式 | 先物化原图，再建立草稿；三图完整后加入上传队列 | 拍摄取消不得破坏旧草稿；存储失败不得提示成功；开始采集后不任意切换模式 |
| 范围标注 | 图片草稿和原图尺寸 | 保存本栏有效区域/排除区域，检测框中心按有效范围过滤 | 排除区域最多8个；视频不带图像 ROI；标注不构成真实边界准确率保证 |
| 视频证据 | MP4；App 时长大于0且≤2分钟，大小≤30 MiB（界面显示30 MB） | 原视频持久保存、上传、播放和人工复核 | 不生成自动数量，不按视频帧简单求和；设备不支持预览时给出明确提示 |
| 可靠上传 | 完整草稿、原客户端包ID与幂等键 | 创建包→逐文件→Manifest→Commit；显示原包进度 | 按完整文件续传，不承诺单文件字节级断点；已成功文件不重复传；原图保留到提交成功 |
| 人工确认 | 有效成员和复核权限；待复核会话；未删除证据 | 非负整数确认，锁定引用媒体；结果进入日报 | 缺理由、旧状态、重复确认、已删证据拒绝；提交结果不确定时查询原会话，不创建替代确认 |
| 媒体查询 | 当前组织、业务日期、可选栏舍 | 缩略图列表、原图与盘点入口；分页加载 | 无权限不能读原图；读取失败不能显示为成功空列表；不暴露对象存储凭证 |
| 报表 | 日期范围、可选栏舍 | 日报按选定日（范围结束日）读取；均值按栏舍和区间计算 | 只统计当前有效确认版本；区间含首尾最多366天；导出最多10,000条记录，超限提示缩小范围 |
| 智能问答 | 已启用问答模型、联网、授权上下文 | 使用单次盘点/当日概览/单栏历史工具，返回事实及来源 | 未启用、无数据、无权限、网络故障分别表达；切换身份丢弃旧回答 |

### 8.9 多模态智能体扩展要求

盘点是首个业务模块。后续视觉、视频、声学、环境和其他业务模块采用独立能力接入，不能仅依靠新增首页卡片表示接入成功。

1. **统一上下文**：传递稳定的组织、栏舍、日期、采集组、会话和证据版本；范围缺失时要求选择，不能猜测。
2. **业务工具合同**：每个工具声明名称、版本、输入、输出、所需权限、超时、错误及证据类型；当前三个固定只读工具是已实现基础，通用动态注册目录为后续设计。
3. **模型适配**：语言模型、视觉计数和未来声学模型分别适配；替换权重不改变正式数量、锁定和审计规则。
4. **数据隔离**：工具每次重新校验组织及有效成员关系；模型输出、照片中的文字、ERP 字段不能作为权限或系统指令。
5. **异步任务**：耗时检测、同步和未来分析形成持久任务；对话结束不应丢失业务进度，失败保留原因并可查询。
6. **能力呈现**：区分已接入、未启用、不可用和规划；没有传感器或模型输出时不展示模拟指标。
7. **写入扩展**：未来新增写工具必须先有受控业务 API、明确操作确认、参数及版本校验、幂等和审计；本期不开放智能体写入。
8. **外部调用**：默认关闭；配置真实接口及必要授权后，最小化发送数据。不得向语言模型发送业务令牌、原始媒体、内部对象 URL 或内部错误详情。

## 9. 端到端流程

### 9.1 正常联网流程

1. 用户登录并选择当前猪场。
2. 选择栋舍和栏舍。
3. 拍照或导入照片，确认栏舍和业务日期。
4. 保存并提交上传包。
5. 服务端接收媒体并创建推理任务。
6. App 或管理端显示检测框和候选数量。
7. 复核员查看原图、邻栏边界、遮挡和重复框。
8. 输入人工确认数量和原因。
9. 系统锁定证据并生成确认版本。
10. 日报和合计只读取确认版本。

### 9.2 弱网流程

1. 选择栏舍并拍照。
2. 原图复制到 App 持久目录。
3. 显示“本机已保存/待上传”，不显示推测数量。
4. 网络恢复后自动或手动续传。
5. 已上传文件不重复上传。
6. 服务端返回检测结果后进入复核流程。

### 9.3 异常流程

| 异常 | 系统处理 |
|---|---|
| 网络断开 | 保留本机证据和上传状态 |
| 408/429 | 进入重试，不永久阻塞 |
| 永久性 4xx | 标记阻塞并提示原因 |
| 推理失败 | 转待人工复核，保留失败原因 |
| 近重复 | 进入复核告警，不自动删除 |
| 锁定证据删除 | 返回冲突，保留审计 |
| 业务版本冲突 | 拒绝旧版本写入，要求重新读取 |
| 智能体不可用 | 采集、上传、复核和报表继续可用 |

## 10. 非功能需求

- 组织隔离必须由后端执行。
- 写操作必须幂等，重复提交不能生成重复业务对象。
- 原始媒体默认私有，访问必须经过授权。
- 生产环境使用 HTTPS，不使用默认密码和调试模式。
- 日志不得记录密码、令牌、私钥或原始媒体。
- 主按钮触控区域不小于 48dp，关键采集操作不小于 56dp。
- 状态不能只依赖颜色，同时提供文字和图标。
- App 重启后已持久化草稿和上传队列应可恢复。
- 服务健康检查区分存活和就绪；模型不可用不能伪装为可计数。
- API、数据库迁移、推理合同和本地数据库均需版本化。

以下为验收目标，未经专项测量不能写成当前实测结果：

| 编号 | 指标 | 验证口径 |
|---|---|---|
| NFR-01 | 已物化草稿和队列在进程退出/设备重启后恢复率100% | 覆盖单图、三图、视频、未入队/已入队；含当前暂停的真机故障 |
| NFR-02 | 同一 Commit 并发20次只产生一个业务任务 | 固定客户端包和幂等键，检查数据库及媒体数 |
| NFR-03 | 主流 Android 冷启动P95<3秒，低端机<5秒 | 固定机型、系统、样本次数及联网条件，独立实测 |
| NFR-04 | 本地2,000栏舍搜索P95<200毫秒 | 在目标设备的本地缓存上测试 |
| NFR-05 | 普通 API P95<500毫秒 | 不含文件传输和模型推理；报告并发和数据规模 |
| NFR-06 | 10MB图片上传额外内存峰值<40MB | 测量客户端及服务端；避免多份整文件常驻 |
| NFR-07 | 管理端4G条件LCP<2.5秒 | 固定网络及设备条件；单独记录实测 |
| NFR-08 | 系统字体130%时核心操作不被截断 | 小屏和大字验证；管理端提供可见焦点与键盘导航 |
| NFR-09 | 上传、推理、失败重试和重复拦截可观察 | 无样本/采集失败显示未知；不伪装零积压或100%成功 |
| NFR-10 | 生产数据可备份并在隔离目标恢复 | 加密介质、哈希、原镜像、媒体和确认值回读；RPO/RTO待业务确认 |

“联网尽快出数”应分别记录上传、排队、推理和结果返回耗时，不用模型单次耗时代替端到端耗时。当前 CPU 试用服务器暂无可承诺的端到端 P95，需实测后确定指标。

### 11.1 关键场景验收用例

| 用例 | 操作 | 预期 |
|---|---|---|
| AT-01 真实盘点闭环 | 选一栏拍摄→上传→核验原图→人工确认→查看日报 | 栏舍和日期一致；确认前不入正式合计；确认后锁定并显示确认值 |
| AT-02 弱网与重开 | 保存三图，传完第一图后断流，退出并重开，再联网 | 原图、方向、范围、栏舍均恢复；续传原包；成功文件不重传 |
| AT-03 重复文件 | 在同组织另一栏提交同文件；另组织再提交 | 同组织被阻断；不同组织不泄露原组织信息 |
| AT-04 遮挡和多视角 | 提交有邻栏排除区的图片及三图采集组 | 范围过滤按合同；三图不直接求和，无法判定转人工 |
| AT-05 未知和零 | 推理失败转复核，填写0及依据并确认 | 候选仍未知；人工0进入日报；不生成模型0 |
| AT-06 锁定与更正 | 普通账号删锁定媒体，管理员更正数量并重放相同命令 | 普通删除拒绝；更正生成新版本，重放不增版本或审计 |
| AT-07 多日平均 | 示例确认23日30头、24日缺失、25日26头 | 仅两天参与，原始均值28；缺失不补0；不替换25日26头 |
| AT-08 组织权限 | 用盘点员、复核员、管理员和不同组织账号分别访问 | 按权限矩阵放行或拒绝；不能通过URL绕过 |
| AT-09 助手降级 | 关闭问答，或模拟模型超时 | 明确不可用；直接采集、上传和复核继续运行 |
| AT-10 备份恢复 | 受控停写后一致备份，并在独立目标恢复 | 历史/当前版本、锁定、媒体指纹、审计和队列可回读；不覆盖原环境 |

验收状态按代码测试、部署验证、Android实测、真实猪群效果分别记录。本文件更新不增加任何运行或真机通过声明。

## 12. 当前发布判断与后续计划

当前版本可用于团队和合作猪场小范围试用，不能直接视为完整生产版。

正式生产前还需要：

1. 完成产品 MySQL、Redis、MinIO 的定期加密备份和恢复演练。
2. 完成真实 Android 弱网、重启、低端机和更多猪场样本验收。
3. 完成研究模型许可、现场准确率和业务批准。
4. 确定长期访问地址与证书续期、生产镜像版本、回滚方案和首批账号；当前公网 IP HTTPS 可用于试用。
5. 继续单独处理此前暂停的断网清后台登录问题。

建议路线：

- **V0.3**：待归属、归属更正、拍摄覆盖提示、补拍流程和批次任务。
- **V0.4**：批次日报、周期参考、只读智能体和证据解释。
- **V1.0**：金蝶 ERP、三视图/视频能力和更多多模态模型，逐项验收后启用。

上述阶段仅表达建议顺序，不承诺交付日期。跨图同猪识别、视频和其他模型需独立准入，不能因版本号变化自动启用。

## 13. 待决事项与风险

| 编号 | 事项 | 当前处理及关闭条件 |
|---|---|---|
| DEC-01 | 用户原述“被盘点即不可删”是否包含AI刚检测完成 | 当前沿用人工确认后锁定；如需检测结束立即锁定，须单独确认并修改状态、删除权限和验收 |
| DEC-02 | 归属错误的受控纠正 | 当前联系管理员核查；不能删后重传；需新增归属更正合同、结果失效和审计后交付 |
| DEC-03 | 金蝶版本、接口及主数据冲突权威 | 获取真实接口、字段和授权；确认手工数据/ERP来源的覆盖策略及回滚 |
| DEC-04 | 跨午夜、时区和历史补录日期 | 当前新采集用设备当天；需确定组织业务日、迟到上传和补录权限 |
| DEC-05 | 多日均值适用性 | 保留确认日数据，均值作为参考；变动台账未接入，不自动推断调栏或死亡 |
| DEC-06 | 现场模型质量 | 遮挡、猪只移动和邻栏可能造成误差；以授权样本、人工金标和独立测试准入 |
| DEC-07 | 离线清后台登录故障 | 用户已要求暂停；保持已知未关闭问题，不写成断网冷启动验收通过 |
| DEC-08 | 数据保留、备份和容量 | 确认媒体保存期限、备份目的地、责任人、RPO/RTO和容量预警；不得自动删除锁定证据 |
