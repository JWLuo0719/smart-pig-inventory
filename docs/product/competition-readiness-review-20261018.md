# 参赛产品审查与一个月打磨计划

审查日期：2026-10-18。目标：金种子杯大学生创业大赛、全国人工智能应用创新大赛等；用户估计准备窗口约一个月。具体届次、学校选拔、赛道、平台和截止时间尚未确认。

## 1. 结论与证据范围

建议把现有产品打磨成“弱网猪场中，以视觉 AI 辅助清点、人工确认和可追溯证据完成可信盘点”的完整成果。优先修数量语义和组织边界，再做证据复核体验、真实场景评价与演示。现有 Flutter + Next.js + Spring Boot/版本化 Provider 架构适合增量优化。

本轮交付为只读审查和实施建议，未修改业务代码、部署、模型批准、手机数据或数据库。审查基于当前工作树（HEAD `f429e4a`，移动版本 `0.1.0+19`），包含已有未提交状态文档；新发现属于源码证据，尚未做修复后的运行验证。没有重跑全量测试、连接真机、启动服务、读取密钥或外部研究图片/权重。历史测试与用户反馈均按原日期引用，不能当作本轮实测。

事实源：[PRD](PRD.md)、[验收标准](acceptance-criteria.md)、[非功能需求](non-functional-requirements.md)、[追踪表](requirements-traceability.md)、[当前交接](../../CURRENT_HANDOFF.md)、[任务契约](../TASK_CONTRACT.md)。开源证据和采纳边界见[对标报告](../research/competition-product-patterns-20261018.md)。

### 值得保留并重点展示的基础

- 离线证据持久保存、草稿恢复、分阶段幂等上传及恢复链路。
- 真实单图 AI 候选与人工确认分离，确认锁图、更正留历史版本、报表只含确认值。
- ROI/邻栏排除、检测框、原图、失败原因已有产品入口，可继续提升可解释性。
- 组织隔离、审计、失败重试、导出、监控和恢复工具已有实现及历史验证记录。

最新交接记录 v19 已完成登录、栏舍同步、任务及采集入口读回；完整上传与复核尚未在该轮走通。视频采集、上传、App 内播放有用户反馈通过，视频自动计数仍关闭。ROI 已有真机截图，但保存回显、服务端过滤与现场标定未完成。后续彩排必须使用同一候选版本重新形成完整证据。

### 若目标赛道确实要求 AI Agent

建议单独评估一个小范围、只读的“盘点助手”：用户问“今天哪些栏需要优先复核，依据是什么”，助手根据登录组织、日期调用已有任务、会话和趋势接口，返回带证据链接的解释和可点击行动。记录所用工具、参数范围、结果出处及无数据/失败情况；盘点确认、更正、删图仍由授权人通过原流程完成。

这是待实施的新能力。当前 [AssistantInsightService](../../services/business-api/src/main/java/com/smartfarm/inventory/inventory/application/AssistantInsightService.java) 是数据库规则服务，并非大模型工具调用助手。应先用赛题确认需求；如指定平台，验证该平台能否接入受控只读接口、身份与数据边界，再做适配。模型提供方、凭据、成本和真实数据外传范围均未决定。不要把规则卡片改名作为智能体交互证据。

该方向与核心修复并行做可行性判断，首周明确做/不做；超过受控范围则缩减，不挤占最后一周彩排。可用合成组织数据验证正常查询、空数据、无权限、越权请求、服务不可用和证据引用正确性；不得以助手生成的数字替代确认报表。

### 避免扩大源码结论

- F01 的共享 DB 为固定 `pig_inventory.sqlite`（[app_database.dart](../../apps/mobile/lib/core/storage/app_database.dart) 166–170），注销仅清身份会话并保留草稿（[auth_controller.dart](../../apps/mobile/lib/core/auth/auth_controller.dart) 113–125）。服务端 [SecurityUploadActor](../../services/business-api/src/main/java/com/smartfarm/inventory/capture/infrastructure/SecurityUploadActor.java) 32–42 仍检查活动组织与成员关系，不能声称服务端越权上传已经成功。实际风险是本地元数据可见、错误组织请求和旧包被误标 blocked。
- F02 对照服务端 [InferenceResultService](../../services/business-api/src/main/java/com/smartfarm/inventory/inference/InferenceResultService.java) 57–67：研究框回退候选只适用于单图。Admin 当前会话总数使用 `selected.count ?? "—"`，每图框数已经按 asset 分组，不把手机缺陷泛化到 Admin 总数。当前单图 ROI 也不能据此判为计数错误。
- F05 是可由布局规则推导的错位风险，F08 是 painter 失效机制；两者尚未做真实像素复现。修复后需要图像/运行证据，不以构建通过代替。

## 4. 最值得投入的体验打磨

### U01：把复核做成核心展示页（B / 中）

已有框、原图、热图和人工输入，下一步让它们组成一个清晰工作台：栏舍/日期 → 原图与标注切换 → 带框全屏缩放 → 目标编号/局部定位 → AI 候选与人工数并列 → 理由与确认 → 已锁定、报表入口。手机原图缩放已有，带框视图尚未连成同一体验。

Admin 当前确认/更正大量使用浏览器 prompt（field-overview.tsx 122–142），建议改成可核对的表单/抽屉，显示候选、人工值、差异、理由和版本。按当前组织角色呈现操作，后端继续负责授权。

先保留现有按总数确认；如新增逐框增删或漏检/误检分类，需先定义版本化纠错证据契约，不能覆盖模型输出或把客户端改框直接当最终检测结果。

验收：密集猪群可逐目标核对；横竖图变换正确；候选不覆盖人工值；确认后的旧版与更正版本可追溯。

### U02：首页与上传呈现“今天还差哪一步”（B / 中）

首页突出一个主要动作：继续未完采集 / 查看待复核 / 开始今日盘点。组织与业务日期固定可见；真实进度必须标明“已确认栏舍/任务”，不与上传完成混淆。保留信息层级和现有蓝绿主题，避免为比赛硬写漂亮数字。

上传队列用作业卡替换以 UUID 为主的文本：栏舍、日期、缩略图、真实上传阶段、已传文件数/总数、最近错误、下一步。采集入队后直接给“查看上传进度”，Commit 后给“查看服务器结果”，保持每种状态都有去向。UUID、checksum 等转入诊断详情。

验收：断网时清楚说明照片已安全保存；恢复后能追到结果；部分失败不被“批量完成”掩盖。状态均来自真实仓库/响应。

### U03：规则研判说清“为什么提醒、接着做什么”（B / 小至中）

当前 [home_screen.dart](../../apps/mobile/lib/features/home/home_screen.dart) 47–54 的研判加载失败静默消失；429–451 的行动只接了部分类型。建议加局部恢复状态，所有行动都连到正确会话/栏舍/日报。展示基线日期、有效确认样本数、候选/确认来源，依据可展开。

采用“数量变化待核实”，给转栏、出栏、漏检等核实方向；没有业务验证不能由数量直接推断疾病。现有固定 0.5 的“高置信”分界（[annotated_evidence.dart](../../apps/mobile/lib/features/inventory/annotated_evidence.dart) 15–16）还低于研究阈值 0.60，可能让所有返回框都显得可靠；应标为模型分数、关联本次模型身份，并说明分数不等于计数准确率。

### U04：图库、中文与视觉一致性（B / 中）

服务器图库目前以文本卡和翻阅按钮为主（[server_gallery_screen.dart](../../apps/mobile/lib/features/gallery/server_gallery_screen.dart) 222–254），可升级为受授权缩略图网格，统一方向中文、视频标记、锁定状态。版本与帮助入口展示构建号、数据同步时间和可恢复指引；环境与模型状态来自可信信息源。

PRD 已确认产品名“智慧猪场场主”，品牌目录名“牧数智核”不自动等于改名授权。参赛材料如需采用“牧数智核 · 智慧猪场场主”，应统一产品与成果名称关系后再改 Logo、启动页、APK、报告与 PPT。

完成一次小屏与系统字体 130% 的核心路径检查，符合现有 NFR；再按余量扩到 150%/200%。重点核对固定 Row、11–12.5 字号、按钮触控、强光阅读、TalkBack 以及趋势/热图文字摘要。美观与溢出结论以新截图/真机为准。

## 5. 模型、业务价值和原创贡献的证据

### 模型成绩卡（A，模型团队与产品并行）

[现有研究评估](../research/team-yolov13-candidate-evaluation.md) 33–50 记载：测试 61 图，MAE 1.049、WAPE 3.75%、误差 ±2 内 93.44%、精确命中 29.51%；61 图标注都为 28 头，覆盖过窄。CPU 稳态 P95 64.1ms 属 Windows 研究运行时，不是手机端或上传至确认的端到端延迟。历史真机候选 19 / 人工 24 是有效误差案例，不能据一次样本判定总体精度。

参赛成绩卡至少列模型/适配器身份、阈值、数据授权与划分、样本数及数量分布、拍摄条件、MAE/RMSE/WAPE/精确命中/最大误差、硬件与延迟范围、失败案例。WAPE 3.75% 不能改写为“准确率 96.25%”；人工确认正确率也不能算作模型准确率。

建议先准备 30–50 个独立授权场景样本用于探索性检查，覆盖空栏/少量/密集/遮挡/邻栏/模糊/光照/设备差异，按栏舍与采集时段隔离，记录独立人工真值。该建议数量不代表统计充分或模型发布准入；正式门槛需事先定义样本量、容差与通过条件。样本取得不足时如实报告限制，不用研究集包装成现场数据。

保留外部数据只读与忽略清单边界；验收集不用于选阈值。新模型/阈值变更按[研究发布边界](../agent-guidance/research-model-release-boundary.md)做新回归、清单、不可变基线对比与隔离回滚，模型批准单列。最终场景成绩卡必须对应冻结的同一模型、阈值与运行配置，不能混合不同候选的成绩；冻结后换模型应重测并重出成绩卡。

### 作业价值（B，第一周就开始采集，不等界面做完）

和至少一个实际使用方核对：谁拍、谁复核、谁付费、使用频次、网络条件、最容易错的步骤。争取若干现场盘点员/场主的结构化试用反馈；这是本地建议，不代表已取得合作或客户。

同类栏舍对比“纯人工”和“AI 辅助＋人工复核”的完整时间与差错：包含拍摄、上传等待、核验、记录/汇总；记录人数、场景、顺序和熟练度。报告中位数、范围和样本，不预填节省比例。试验顺序轮换、独立人工真值先记录，减少记忆和熟练度影响。

成本模型列清软件/边缘设备/部署培训/维护与模型服务成本，区分当前实付、估算和未报价。价格、规模、收入需要真实调研/合同支持；可先展示测算假设，不虚构订单或融资。
