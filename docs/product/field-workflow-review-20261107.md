## 判断

保留现有组织—栋舍—栏舍、证据上传、候选检测、人工确认和报表底座，优化现场工作流。重点从“上传一张图片得到数字”转向“有明确栏舍归属、有采集覆盖、有证据、有确认口径的盘点”。UI 重设计应体现这些约束。

## 优先优化的现场流程

### 1. 在采集入口确认栏舍归属

建议采用“选择/扫码栏牌 → 显示猪场/栋/栏/日期 → 拍摄或导入 → 上传前复核归属”。二维码解析为稳定栏舍身份，并用当前组织的已缓存主数据验证，不能凭二维码文字就创建或切换到任意组织。

离线时已有缓存的栏牌仍可使用；未缓存或未知栏牌应提示无法验证，不能冒充已确认归属。二维码解决的是用户选择哪个栏舍，仍需确认照片内容属于该栏。

批量导入允许在本机按栏分组；未分配的文件保留在待归属区。照片 EXIF、拍摄顺序和文件名只能辅助推荐，不能自动当作栏舍或业务日期的事实。尽量在原图旁显示栏舍标识与时间，保留原图，不通过修改原图水印替代可审计元数据。

### 2. 提供“本栏范围与排除区”工作流

当前矩形有效区/排除区可以继续使用，界面用“只计算本栏”“不计入本栏”代替 ROI 参数名。对邻栏猪明确排除；跨边界猪提示检查归属，不靠框中心落点作绝对保证。

料槽可能只挡住猪的一部分。不要把料槽区域一概划为不计数区，否则会误排除属于本栏的猪。对遮挡应提示换角度补拍；完全不可见的猪没有视觉证据，不能声称模型能可靠补出。

固定拍摄点可减少差异；只有相机位置和视角经过核对时才考虑复用范围模板，手持拍摄不能无条件套用旧坐标。

### 3. 把覆盖与质量检查放在数量之前

采集过程中提示是否拍全本栏、是否有邻栏入镜、是否明显模糊/反光/遮挡。第一阶段可以采用明确的拍摄指引与人工检查；尚未实现的自动质量评估不得在界面显示为已检测通过。

单图不完整时，引导补拍同一采集组中的其他视角。补充图需要尽量短时间内按固定顺序采集，并保留重叠区域供复核。猪在移动、外观相似或遮挡严重时，不保证跨图匹配成功；无法判定的情况应要求人工核对或重拍。

### 4. 区分三种重复和一种归属错误

| 情况 | 处理建议 |
|---|---|
| 同一文件再次提交，含跨栏提交 | 组织范围指纹阻断，向有权限的用户提示原记录及其栏舍/日期；重复点击的幂等续传继续恢复原上传包 |
| 压缩、裁剪、截图或相近角度的照片 | 精确指纹不再相同；相似性只能形成风险提示，不能宣称已彻底识别或自动删除 |
| 不同照片拍到同一头猪 | 属于跨图目标关联，需要采集约束、模型/几何验证与人工复核，不能用图片指纹解决 |
| 同一照片选择了错误栏舍 | 提供受控的归属更正，保留源证据和审计，撤销旧候选并重新处理；已确认记录走后台更正和新版本，不直接改历史 |

当前 UploadService 对软删除照片也返回 DELETED_DUPLICATE_IMAGE，因此不能把“先删再传到正确栏”设计为正常纠错路径。归属更正的接口、权限、幂等、锁定与结果失效需另行设计，实现前界面只能作为拟议功能。

### 5. 明确确认与删除的业务时点

建议状态链：已保存 → 待上传 → 已提交/检测中 → AI 候选待复核 → 人工已确认并锁定。

“AI 出了数量”不等于“正式盘点确认”。建议当前锁定时点继续采用人工确认；普通用户可在许可范围内处理未锁定错图，相关候选需要失效或重新检测。确认后改数生成新版本，后台对证据的处理必须有理由和审计。

如果猪场实际制度要求 AI 检测一结束就锁定，应单独变更状态和权限规则，不能将这项歧义藏在一个“已盘点”标签中。

### 6. 给多日平均增加适用条件

建议创建“月底盘点批次”，明确目标日期、参与日期和应盘的 20 个栏舍。每个栏每天只有一个当前有效的人工确认版本；多次采集不增加该日权重。

跨日平均可能缓解部分随机误差，但不能修复持续遮挡造成的系统性漏检。真实猪群变化时，平均值也不代表目标日存栏。例如示意数据：23/24/25 日分别为 30/28/26 头，均值为 28，但 25 日记录为 26，不能自动把 28 当成 25 日事实。

第一阶段同时展示“目标日确认数量”和“周期平均参考”，明确参与日期、缺失日期和覆盖率。未确认/未盘点是未知，不得填 0。出现猪群变动应提示不可直接比较，或按另行确定、可审计的变动台账规则处理；没有数据源时不自动校正。

整栋报表显示逐栏明细、已确认栏数/应盘栏数及已确认合计。若只确认 18/20 栏，合计必须明确为部分覆盖，不能显示成整栋完整存栏。跨栏汇总还需要一致的时间口径，避免转栏前后各计一次。

## 第一阶段建议顺序

1. 栏舍归属和纠错：显著栏舍标识、批量导入待归属、受控归属更正；扫码栏牌可作为新增入口。
2. 可靠采集与补传：每个草稿有完整组织/栏/日期/采集组身份，清楚区分本机保存与服务器接收，按栏恢复上传。
3. 本栏范围、遮挡补拍和人工复核：以现有 ROI 能力为基础，完整表达候选、边界疑问与正式确认。
4. 栏舍图库和锁定：按栏按日翻阅，错图处理与候选失效、锁定冲突、后台更正一致。
5. 批次与报表：逐栏任务矩阵、日有效版本、目标日/平均参考区分、缺失日期和覆盖率。
6. 单独验证金蝶真实接口和三视图/视频自动计数；未经验证不在试用 UI 中承诺可自动完成。

这是建议的交付顺序；本评审不等于用户已授权开发所有新增功能。

## 对新 UI 的影响

用户补充强调产品的智能体属性与扩展性。模块边界、工具接入、上下文助手及演进建议见 [智能体扩展性评审](agent-extensibility-review-20261107.md)。盘点是首个业务模块，新增现场流程先成为可复用业务能力，再按权限向助手开放；当前只读范围不因设计讨论扩大。

除首页、采集和复核页外，Stitch 设计应包含：栋舍下逐栏任务列表、待归属素材、批量导入分栏、本栏范围/邻栏排除、左中右采集组、按栏上传队列、栏舍按日证据库、归属更正及锁定提示、批次日报矩阵。

每个页面体现三项关键信息：属于哪个栏舍；当前证据和处理状态；数量是候选、人工已确认还是未知。不得只用一个“完成”状态概括已保存、已上传和已确认。
