## 1. 任务与选题决定

- 本届保底作品：**牧数智核——面向智慧猪场的视觉感知与可信盘点智能体**。
- 命题领域：通用赛道—其他，具体场景为智慧农业/生猪养殖。依据用户提供的报名界面；尚未操作报名系统。
- 主要用户：盘点人员、复核人员；场长查看当天待办及确认记录作为辅助场景。
- 核心问题：如何将一张猪栏照片形成有证据、可复核、可追溯的盘点结果，并让使用者通过自然语言理解当前状态、依据和下一步。

本轮交付是开发计划与要求追踪。后续按计划开发、测试和准备本地材料；实际公开部署、付费资源、数据外发和赛事提交按各自授权执行。本计划不授予这些外部操作权限。截止前必须形成可评审作品，不能将“代码完成”当成“比赛交付完成”。

## 4. 保底功能与实现方式

### 4.1 只保留一个清楚的产品流程

1. 盘点人员选择栏舍与业务日，拍摄或导入一张授权照片；需要时设置 ROI/邻栏排除区。
2. 上传完成后，展示模型候选、原图检测框及状态。合法零、未知、失败分别处理；待处理时不显示预估数量。
3. 复核人员核对候选与图像，人工填写/确认数量，形成锁定证据与确认记录；后续更正形成新版本。
4. Agent 解答“这次有何依据、还差什么、接下来做什么”；使用者可看本次受权证据页。
5. 场长查询当天未完盘点及某栏确认历史。数量变化只解释记录差异与覆盖，原因没有依据就说明未知。

### 4.2 在现有栈内新增最小在线 Agent

建议默认复用 Next.js 的独立评审/对话页面和 Spring 的业务授权与适配层：网页 → 受认证 Agent 入口 → 受限模型工具循环 → 三个工具执行器 → 既有组织范围业务 API/服务 → 带引用回答。视觉推理继续走原 Python/Runner 合同。新 HTTP 合同先写 `contracts/openapi.yaml`；路径、流式与错误 schema 在 A1 批次确定，不能让前端自行绕过业务授权。

模型负责理解问题、选择允许的工具、解释已取得证据；数值和状态取自工具结果，合计/差值等计算在确定性代码完成。页面独立显示事实卡（日期、候选、确认、状态、引用）与模型解释；校验引用及关键数量，验证失败时提示无法可靠生成解释，不把模型自由文本变成新的盘点权威。

- 三个工具保留现有上限和状态：当日最多 50 行且展示 `hasMore`，历史最多 90 天，缺失不补零。超范围请求澄清或缩小范围，不把截断列表称全场结论。
- 每次调用从认证上下文取得组织/角色；不接受模型传 org、token、SQL、任意 URL 或对象路径。对话历史在退出/切换组织时清理；评审账号不具有确认、更正、删除、重试或管理员能力。
- 不向模型传原始猪场照片、个人身份、业务密钥或对象存储地址；只用经授权的最小结构化字段和审核过的操作说明。若托管模型不在数据授权范围内，先用允许外发的隔离演示数据，明确标识来源。
- 工具返回文字、用户输入、知识文档均按数据处理，不能成为新工具权限或系统指令；引用仅可由本次实际读回生成，点击后再次走业务授权。
- 首版使用短期会话上下文和脱敏调用轨迹，不新建长期聊天/向量数据库。设置模型/工具超时、取消、调用轮数、每账号限流及额度预算；初始内部上限可取每问 3 轮、6 次工具调用、60 秒总截止，按实测调整，页面先显示处理中和可取消状态。
- API 密钥仅在服务端安全配置。先做一个工具的真实调用再扩成三个；没有可用额度/接口时允许继续契约开发，但不得记为在线 Agent 交付。

JoyCode 可用于开发与平台适配验证；它是否承担在线运行由 A0 的实际部署验证决定。IDE 助手、配置分享链接和应用 API 额度不是同一交付。保底不要求接 MCP、多 Agent、RAG 向量库或迁移框架；如比赛平台实际要求额外适配，再按已确认接口增加薄适配层。

### 4.3 数据和知识准备

建立可追溯来源表：来源、日期/版本、授权范围、处理步骤、用途、局限。主数据为授权照片与独立人工真值、现有系统的盘点/确认/更正记录；知识为团队审核的拍摄、补采和复核 SOP，注明“团队操作规范”。可引用已核实的行业公开资料解释背景，但不冒充产品实验数据。小规模知识可版本化为只读条目，回答引用条目 ID 与版本；没有检索实现就不宣称建成 RAG。

演示环境至少具备：一条真实单图候选、一条人工确认记录、一条更正链、一个缺采/未知案例、一个受控推理失败案例、一个有覆盖/缺失说明的历史查询。真实授权数据与合成故障数据分别标识；没有真实连续历史时可以展示明确标记的合成历史交互，不据此主张经营趋势或业务收益。评审账号只访问专用比赛组织，不连生产组织；原始研究集保持只读且不进入 Git、镜像或公开评审数据。

## 5. 三个必须实演的提示词

“今天”在评审页显示实际业务日期；历史样例用固定可见日期，避免评委访问当日无数据。括号中参数由界面当前选中记录或真实业务 ID 绑定，不预制回答。

| 场景与提示词 | 实际工具 | 必须看到的结果 |
|---|---|---|
| Q1：“请检查这次盘点（当前会话）：AI 候选数和人工确认数分别是什么？还需要核对什么？” | `inspect_session` | 候选/确认/未知分列、状态和受权证据引用；尚未确认时明确不入正式报表。不能仅凭框分数断言准确或找出真实漏检 |
| Q2：“在所选业务日，还有哪些栏舍没完成盘点或需要复核？分别下一步做什么？” | `get_day_overview`，需要时 `inspect_session` | 缺采/处理中/待复核等事实、覆盖数和截断说明、建议及可进入的业务页；简单待办归类即可，不增加未验证的智能风险排名 |
| Q3：“比较这个栏舍最近 7 天的确认数量；这次结果能直接解释成猪只减少吗？” | `get_pen_history`，需要时 `inspect_session` | 仅使用确认记录、业务日/缺失/样本数；说明数量记录差异不等同于死亡或转出原因；历史不足时明确不足 |

每个示例保存：输入、模型标识/提示词版本、工具参数与脱敏结果、最终输出、引用读回、耗时和用量（如接口提供）。更换栏舍/日期、追问“依据在哪”、询问不存在记录时必须动态响应。至少一条显示多工具组合；不以预录视频替代可交互 URL。

| 11/6 | 必要模块自动门禁与运行回归；集中同版本真机、弱网/坐标/身份验收开始 | 修复阻塞缺陷；所有跳过与失败明确列出；冻结新增功能范围 |

止损规则：11/3 未落实模型/资源/授权时，优先缩小数据与部署规模，使用已授权模型或隔离演示环境；不能用假对话解决。11/5 未形成真实交互/外网访问时，暂停所有增强和界面装饰，集中补 A2/A6。11/6 后不换模型权重、不加框架、不开发新赛题；如必须修复则重新绑定版本与检查。缺真实精度样本时降低“精度/收益”的主张，保留研究集证据并明确局限；缺在线 Agent/可访问账号时仍属于必交缺口，PPT、录屏或本地模型演示不能替代。

## 8. 验收证据与内部质量门槛

### 8.1 原系统门禁继续执行

按实际修改模块执行 AGENTS：Spring `mvn test`/`mvn verify`；Admin `pnpm test/lint/typecheck/build`；Flutter `dart analyze .`、`flutter test`、`flutter build apk --debug`；Inference 修改时 `python -m pytest`；基础设施修改时 `docker compose config --quiet`。现有 34 项 Docker 跳过不是通过，必须恢复相应集成；新增 Agent 业务/auth/模型适配与浏览器回归纳入对应模块。

固定 Admin、回调、导出、故障等隔离栈按变更及未完成验收选择，遵守 AGENTS 的固定项目/端口，不重指 P0。核心确认、更正、锁图、报表需 HTTP/MySQL 语义读回。保留 `MODEL_APPROVED=false`、研究候选和人工复核；不把批准开关作为演示捷径。模型身份/阈值/适配器若变，按[研究发布边界](../agent-guidance/research-model-release-boundary.md)做完整回归、清单、基线比较与隔离回滚，不能赶期跳过。

[现有集中验收表](../development/competition-acceptance-runbook.md)继续覆盖真机、弱网、EXIF/ROI/检测框像素、130% 字体和连续三次彩排；本计划增加 Agent 与外网交付部分。源码、APK、镜像、Flyway、模型及提示词版本共同固定；修复后重验相关场景，旧 v20 BuildOnly/v21 Debug 不替代新联网候选。

### 8.2 Agent 评价

内部首轮最少 18 个案例：6 个正常（3主题各2种表达/参数），6 个数据边界（零、缺失、失败、未确认、截断、无历史），6 个安全/恢复（跨组织、失效登录、要求写入、提示注入、模型超时、切组织后的迟到响应）。现有 36 个合成工具夹具继续保留，但独立统计，不冒充 18 个在线 Agent 案例。

所有安全案例必须拒绝越权且无业务写入；三主题至少各一次真实模型/工具/引用链路成功。数据边界不得伪造数值/引用，不得候选当确认或隐瞒截断。记录任务完成率、事实字段一致率、引用有效率、失败数、耗时与用量；保留未通过案例并修复，关键错误未清零不冻结。内部目标仅约束这组测试，不外推为普遍正确率。

### 8.3 视觉与业务评价

沿用[成绩卡](competition-model-scorecard.md)分开报告研究集、授权现场候选、人工确认业务结果。内部采样目标为至少 30 张有独立真值的授权照片，覆盖密集/遮挡/光照/空栏；至少 10 次完整业务流程记录。数量不足不补造，不把演示样本当跨场泛化结论。两名标注者独立清点并复核分歧，不能看模型答案后把它当真值。

固定已有权重与阈值；给出有效候选 MAE、完全一致率、全部请求数、候选失败/缺失数与覆盖率。人工确认值不能用来“提升”模型计数精度。记录采集→候选→人工确认的实际用时，人工对照保持相同作业范围；无可比对照则只报用时，不报提升百分比。研究集历史数字必须注明日期/版本，不能当本次现场成绩。

## 9. PPT、视频和评审入口设计

### 9.1 20 页 PPT 编排

| 页码 | 内容 | 所需证据 |
|---|---|---|
| 1 | 匿名封面、题目、一句话价值 | 与报名题名一致；无身份标识 |
| 2 | 业务背景与现有盘点问题 | 已核实场景与资料来源，未核实访谈不引用 |
| 3—5 | 真实数据渠道、授权/标注、SOP 知识、预处理与用途 | 来源表、样本统计、去重/ROI/脱敏流程、知识条目示例 |
| 6—9 | 视觉→复核→确认→Agent 方法；工具/业务边界；实例逻辑 | 架构图、真实调用链、同一业务实例和引用 |
| 10 | 1—2 项可证实的应用创新 | 视觉证据与自然语言解释联动；未知/候选/确认及不可变版本的可追溯设计。无证据不写“首创/领先” |
| 11—16 | 模型/业务/Agent 结果；失败例；2—3 条改进建议；1—2 类风险与应对 | 实测分母、版本与限制；隐私/越权、错误解释/人工复核；效果不靠预测营收证明 |
| 17—19 | 在线界面及 Q1—Q3 实际输出、证据链接与入口 | 可读截图和真实输出；不在公开 PPT 放秘密凭据，按官方受控字段交账号 |
| 20 | 适用范围、已验证/未验证项和后续路线 | 其他选题仅为后续方向，评审体验指引，关键来源索引 |

各页短注直接标来源；页数分配已在官方建议范围内，总页数不叠加各章节最大值。原商业计划书只复用已核实背景和需求，不直接搬财务预测、合作、论文/模型改进与未落地功能作为结果。

### 9.2 5分40秒视频脚本

0:00—0:25 问题与目标用户；0:25—0:50 数据/方法；0:50—2:10 单图采集、候选、复核确认、报表；2:10—4:10 三个 Agent 提示词与输出/引用；4:10—4:45 一个失败/未知案例；4:45—5:20 实测结果与创新；5:20—5:40 局限与入口。使用本次候选录屏，删等待段时明确剪辑，不伪装实际响应速度。讲解匿名，避免任务栏/终端/账号/桌面通知泄露身份或秘密。

### 9.3 可持续评审入口

提供 URL、专用账号、初始操作、三个真实案例参数、已知限制和故障联系机制。登录凭据只通过官方提交字段/受控交付传递，不入 Git、不硬编码进 URL/前端、不用真实管理员账号。界面可引导只读评审；App 写入链路由团队演示并提供真实证据。评审不要求安装 JoyCode 或加入团队工作区。

外部两次独立会话验证登录、三问及引用；一次服务恢复后复测；至少维持至校赛结束 11/20，晋级后按 12/11、12/27 相应延长并覆盖官方补评安排。期限是团队运行计划，最终以评审通知为准。额度预警、账号有效期、证书有效期和维护人必须落实；不把临时本机隧道当稳定完成证据。
