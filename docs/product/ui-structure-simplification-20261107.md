# 移动端界面结构精简方案

日期：2026-11-07
适用产品：智慧猪场场主 Android App

## 一、问题判断

当前界面的问题不是功能数量多，而是同一个业务对象被重复表达：

- **导航重复**：底部已有“首页、任务、盘点、图库、我的”，首页又有“态势大屏 / 盘点台账”切换，首页矩阵还提供一套任务筛选，任务页又提供一套任务列表。
- **状态重复**：网络状态、待上传数量、今日进度、协同研判、最近作业分别占据多个卡片，用户需要拼接它们才能知道下一步做什么。
- **能力重复**：视觉盘点、盘点证据工具、拓展分析、智能体能力模块分别展示，用户难以判断哪些是当前可用能力，哪些只是规划。
- **动作重复**：首页开始盘点、底部盘点、栏位卡片进入采集、最近作业继续入口都能进入相近流程，但主次不清。
- **信息密度不均**：顶部范围、摘要卡、矩阵、研判卡、最近作业卡层层堆叠，真正关键的“哪个栏、证据到哪一步、下一步是什么”反而不够突出。

这会增加现场人员的选择成本，也容易把“已保存、已上传、已检测、已确认”误认为同一个完成状态。

## 二、总体方案：以“当前栏舍任务”作为唯一主线

界面围绕一个对象组织：

> 当前猪场 / 栋舍 / 栏舍 + 业务日期 + 证据处理状态 + 下一步操作。

每个页面只回答三个问题：

1. 我现在处理哪个栏舍？
2. 证据处于什么状态？
3. 我现在应该做什么？

### 建议的一级导航

保留四个入口：

1. **工作台**：今天的栏舍任务、覆盖率、继续上次作业、报告入口。
2. **盘点**：选择栏舍并拍摄或导入，进入上传和复核流程。
3. **证据**：按栏舍和日期查看照片、视频、上传状态和锁定状态。
4. **我的**：账号、组织、同步、存储、帮助和退出。

“任务”不再单独占一个一级入口。任务矩阵和筛选直接放在工作台；“报告”从工作台的当前范围进入；“上传队列”从工作台顶部状态进入。这样保留能力，减少入口。

如果必须保持五个底部入口，建议第五个入口命名为“报告”，并只承载跨栏、跨日结果；不要同时保留“任务”和“盘点台账”两套任务入口。

## 三、页面调整

### 1. 工作台：从多卡片改为一个任务面板

工作台只保留四个区域，按顺序排列：

1. **范围栏**：猪场、栋舍、业务日期；只出现一次。
2. **今日任务面板**：覆盖率、已确认栏数、待处理栏数、正式合计。点击数字可筛选矩阵。
3. **栏舍矩阵**：每栏只显示编码、状态、已确认数量；点击后进入该栏当前任务。
4. **继续作业条**：只有存在本机草稿或待上传时显示。

移除或改为二级入口：

- “态势大屏 / 盘点台账”切换，改为矩阵顶部的一个筛选按钮。
- “协同研判”默认不占首屏；只在有提醒时显示一行提醒，点击进入详情。
- “拓展分析”和“智能体能力模块”移到“更多能力”，且显示真实可用状态。
- 最近作业不再做大卡片，改成继续作业条。

### 2. 采集页：只保留一个主动作

采集页顶部固定显示完整栏舍身份：猪场 / 栋 / 栏编码与名称 / 业务日期。

页面主体只保留：

- 取景或照片预览；
- “拍照”和“从相册导入”两个同级入口；
- 保存状态；
- 一个主按钮：**保存并提交**。

三视角、视频、范围设置、待归属和批量导入放入“更多采集方式”，不与单图流程并列争夺注意力。断网时主按钮文案变为“保存到本机”，并明确联网后再上传。

### 3. 复核页：只保留两种数量

复核页固定按以下顺序显示：

1. 原图和检测框；
2. **AI 候选数量**；
3. **人工确认数量**；
4. 修正原因；
5. 一个主按钮：**确认并锁定**。

“补拍”“本栏范围”“邻栏排除”作为当前证据的问题处理入口，不再各自做成大卡片。未确认的数量不能进入正式合计。

### 4. 证据页：用筛选代替多套图库

只保留一套证据列表，筛选条件为栏舍、业务日期、状态。状态标签统一使用：

- 本机已保存
- 待上传
- 检测中
- 待人工确认
- 已确认并锁定
- 失败待重试

不再分别设计“照片库、视频库、待上传库、盘点记录库”。这些是同一证据对象的筛选视图。

### 5. 智能体：做上下文入口，不做第六个主导航

助手从工作台、栏舍、证据和报告详情进入，并自动携带当前范围。首期只提供只读查询和打开原记录：

- 今天哪些栏还没确认？
- 03 栏这次盘点是什么状态？
- 03 栏最近几天的已确认数量是多少？

助手不可用时，采集、上传、复核和证据查看仍可独立使用。助手不能直接确认、改数或删除证据。

## 四、状态与组件统一规则

### 状态只保留一条链

`已保存 → 待上传 → 已提交/检测中 → 待人工确认 → 已确认并锁定`

失败是旁路状态，可重试；离线是网络条件，不是业务完成状态。

### 每个任务只显示一个主状态

例如：任务卡显示“待人工确认”，旁边可用小字说明“服务器已接收”。不要同时用多个彩色徽章表达同一阶段。

### 每个页面只允许一个主按钮

- 工作台：开始盘点 / 继续作业
- 采集页：保存并提交
- 复核页：确认并锁定
- 证据页：打开当前记录

其他操作使用文字按钮或溢出菜单。

## 五、实施顺序

1. 先合并工作台的重复入口：去掉首页双模式、重复任务卡和默认研判卡。
2. 再统一证据状态和任务卡组件，保证所有页面使用同一套状态文案。
3. 把报告、更多分析、助手改为上下文入口，不增加一级导航。
4. 最后再补扫码、批量待归属、三视角和批次盘点等扩展流程。

## 六、验收标准

- 新用户从打开 App 到开始某一栏拍摄，最多经过：选择范围、选择栏舍、拍摄三步。
- 工作台首屏不出现两个以上“开始/继续盘点”主操作。
- 同一栏舍在工作台、证据页和复核页显示相同的状态文案。
- 用户不打开二级页即可知道覆盖率、待处理栏舍和下一步操作。
- 任何展示数量都明确是 AI 候选、人工确认或未知；未知不显示为 0。
- 模型、ERP、姿态、估重等未接入能力不在首屏占用结构位置。

## 七、0.2.2+26 实施结果

本轮已落地四入口（工作台、盘点、证据、我的），首页移除双模式和重复任务列表，保留四列栏舍样式。历史任务和更多能力从“更多作业”进入，报告和助手为次级入口；重复范围、上传指标及图例已合并，最近作业变为紧凑条。规则研判保留且默认折叠。

本次主要精简导航和工作台。证据库深层页面、采集和复核的后续精简仍可继续迭代，不能将全部方案标为已完成。当前版本仍待手机覆盖安装和现场操作验收。
