# 功能正式候选部署说明

本轮按原始盘点需求开发，模型准确度研究后置。正式服务器、域名、首批猪场/账号尚未确定，因此不能称为已正式上线。局域网签名 APK 也不能替代正式部署验收。

## 交付内容与边界

- 当前猪场资料修改，栋舍/栏舍新增、编辑、启停；操作按组织鉴权，保存幂等命令、版本和审计。新猪场及首位管理员由目标部署的 bootstrap 配置初始化。
- 手机按日期/栏舍读取服务器图库、本地证据翻阅、错图删除；确认媒体锁定，后台管理员带理由覆盖删除。删除证据后原待复核会话不再允许确认。
- 手机历史任务、日报、按栏跨日综合；管理端历史查询与 PDF/XLSX 导出保留已确认数据口径。新待复核任务不覆盖当天已确认投影。
- MP4 证据采集/导入、持久保存、队列上传、播放和人工复核。手机限制 2 分钟与 30 MiB，服务端拒绝超过 30 MiB 的视频 manifest；没有视频计数或跨图自动去重承诺。
- 金蝶同步需对方正式 API 文档及账号，当前采用人工维护。

## 独立部署准备

1. 在目标服务器使用独立项目 `pig-inventory-production`，不可复用 `pig-inventory-p0` 或自动化测试的数据卷。先确认 MinIO 作为外部组件的分发/许可方案，或选定兼容的替代对象存储。
2. 从 `production.env.example` 建立权限受限且不入 Git 的实际环境文件，填入目标 HTTPS 域名、初始猪场/管理员、互不复用的随机密钥。研究模型保持关闭，`unavailable` Provider 返回待人工复核且不产生候选数量。
3. 将通过验证的 Business/Admin/Inference 镜像推送至选定仓库，填入 `仓库@sha256:摘要`。配置检查不认可 `latest`。本轮增加 V12 主数据命令和 V13 视频枚举迁移，首次启动由 Flyway 执行，不手工修改旧迁移。
4. 执行 `pwsh -NoProfile -File scripts/test-production-configuration.ps1 -EnvironmentFile <实际文件>`。输出仅是配置检查，不证明服务上线。环境变量会影响 Compose 插值，检查和启动必须使用同一环境。
5. 在主机配置受信任 HTTPS 反向代理，转发至 `127.0.0.1:8088`，保留 30 MiB 上传上限和足够传输超时；不要直接暴露 MySQL、Redis、MinIO 或推理端口。证书续期、DNS、主机重启恢复均在目标环境验收。
6. 正式启动命令为 `docker compose -p pig-inventory-production --env-file <实际文件> -f docker-compose.yml -f docker-compose.production.yml up -d --wait`。当前没有执行该命令。

## 发布与恢复验收

发布前保留旧镜像摘要、数据库一致性备份、对象存储证据副本，以及与备份对应的迁移版本。暂停写入再取数据库/媒体一致性快照；备份加密并限制访问。在独立恢复项目实际还原并核对组织、确认版本、锁定证据和媒体 SHA-256，未经恢复演练不能声称备份可用。数据库已升级后不盲目回滚不兼容的旧程序；必要时在停写窗口恢复整套一致性快照。

目标环境需要实际验证登录/刷新、主数据维护与手机同步、图片和视频上传/续传、按栏日期图库、跨组织拒绝、确认锁定、管理员带理由覆盖、历史日报与均值、PDF/XLSX。记录镜像摘要及 Flyway V13，不能用健康的旧镜像作为新功能证据。

域名确认后使用 `scripts/build-release-apk.ps1` 重新构建同一签名的正式 APK，并在实际网络安装覆盖验证；不得换签名或清除手机草稿。模型审批、功能验收、签名构建和公网发布分别记录。

视频播放使用 Flutter 官方 [video_player](https://pub.dev/packages/video_player) 的本地文件控制器；服务端媒体通过应用鉴权下载到临时文件播放，关闭后清理该临时副本，原始证据不变。

本地恢复工具与合成演练已完成，操作见 [一致性备份与隔离恢复](backup-recovery.md)。这补齐本地恢复开发证据；目标服务器的加密异机恢复和实际切换仍须单独执行。
