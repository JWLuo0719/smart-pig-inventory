# JoyCode 客户端公网连接修复

2026-11-06 实测：将本机 JoyCode 用户设置中的 `server.baseUrl` 设为 `https://joycode.jd.com` 并重新加载窗口后，用户再次从官网点击已有项目的“IDE 打开”，客户端成功进入 `mushu-ai-race` 的 SSH 工作区，并实际打开远端 `App.java` 读取模板代码。无需连接不明来源的深信服 VPN。

## 故障与验证

原先客户端创建项目及读取项目详情均访问 `http://joycode-api-saas.jd.com`。DNS返回私有地址，直连超时。网页能够创建远程项目；网页打开链接也已到达客户端，但IDE在获取项目详情时失败。

官网公开前端配置指向公网云控制台 `https://joycode-devcloud.jd.com`。对官网 HTTPS 网关的对应管理路径进行无凭据检查可得到401，而非连接超时；401仅证明网关可达，不单独证明账号或接口兼容。随后通过客户端自身正常授权链路复测，工作区连接及远端文件读取成功，才作为修复证据。未导出、打印或手动转发登录令牌或SSH私钥。

仅修改本机用户设置 `server.baseUrl`；其他设置值经比较保持一致。原配置备份及修改记录留在忽略的 `tmp/joycode-network-repair-20261106/`，不能上传该目录。当前保留已验证的HTTPS设置。平台升级或企业私有部署时需重新确认服务器配置，不能把此公网地址无条件套用于其他租户。

## 仍待完成

- 本机Windows OpenSSH额外只读检查被现有 `.ssh/config` ACL阻止，提示Everyone权限过宽。随后仅为本项目生成忽略目录中的隔离SSH配置，限制该临时文件为当前用户访问，并保持 `StrictHostKeyChecking=yes`；连接已到达远端SSH服务，但因本机没有可信的ED25519主机密钥记录而拒绝。没有关闭主机密钥校验，也未改动原SSH配置或其ACL。CLI尚未验收，不影响已实测的JoyCode远端文件读取结论；自动上传前需取得可信的主机指纹并完成核验。
- 尚未上传业务源码、执行云构建、迁移数据库、验证真实模型或正式评审入口。未新建额外云资源、变更套餐或确认按量付费。
