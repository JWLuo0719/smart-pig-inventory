# `eg/` 遗留系统处置记录

## 可借鉴

- Flutter + 管理 Web + Java 业务 API + Python AI + MySQL/MinIO 的宏观分层。
- 组织、栋舍、栏舍、任务、媒体、复核、报表和部署问题清单。
- 蓝灰运营视觉和移动端五入口的信息密度。

## 不直接迁移

- 源码、SQL、图片、字体、模型、文案和产品名称。
- 同步 multipart 上传、临时目录媒体缓存、进程内视频线程池。
- 无版本模型、近重复直接拒绝、缺少原因的解锁/人工改数。

## 已发现风险

- 服务端/管理端没有清晰项目许可证；Flutter 子工程 MIT 范围尚待权利人确认。
- 部署包携带 AGPL Ultralytics 源码，后端使用双许可证 iText。
- 部署目录包含 `.env`，登录实现记录明文密码，MinIO 设置匿名下载。
- 自动化业务测试不足，数据库迁移依靠手工 SQL，核心类和页面体积过大。

## 结论

路线 B+ 使用相同类型的技术栈独立实现。任何未来代码迁移都必须先取得覆盖修改、部署、竞赛/软著和商业化范围的书面授权，并完成第三方许可证审计。
