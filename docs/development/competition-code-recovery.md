## 检查与修复

在仓库根执行`git status --short`，先确认没有尚未保存的修复；使用`git log --oneline`、`git show <提交>`和`git diff <起点>..<终点>`选择需要对照的具体改动。修复应在当前分支产生新提交，避免改写这些已记录的回退点。

需要撤销时，按依赖从最近改动向前使用`git revert <提交>`生成可追溯的逆向提交，再执行受影响模块门禁；出现冲突时保留现有文件并逐项解决。不要使用`reset --hard`、`clean`、卸载App或删除数据库/媒体卷来实现代码回退。合同、服务端和客户端须一起评估，不能把撤销路由后的404解释为业务空数据。

当前代码批次不新增数据库迁移，Flutter保持Drift v6，签名/TLS/模型身份与原图不改。代码回退不会撤销已经发生的业务确认或更正；业务历史必须继续保留，数据恢复另走[冷备份恢复流程](../deployment/backup-recovery.md)。已应用Flyway迁移不得编辑或回删，未来若有迁移需单独设计前向修复。
