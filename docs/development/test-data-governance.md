# 测试数据治理与夹具准入

## 分层

| 层级 | 用途 | 可进入 Git/CI | 当前状态 |
|---|---|---|---|
| 合成夹具 | 单元、合同、E2E 自动化 | 可以 | 优先建设 |
| 外部 YOLO 研究集索引 | 本机手工验证、候选覆盖分析 | 仅脚本；生成清单不可进入 Git | 已接入只读清单流程 |
| 已授权业务金标集 | 推理回归、部署评审 | 不进入 Git；放受控存储 | 待取得授权、版本和审核记录 |
| 现场用户媒体 | 真实业务 | 不可进入 Git/CI | 仅 MinIO 私有桶与审计链路 |

## 当前研究集的定位

外部 `agent-base/dataset` 有 YOLO 格式的图片与单类猪只标注。它可协助验证文件处理、检测结果解析和单图数量计算，但不能替代以下内容：

- 左/中/右同栏采集组；
- 真实栏舍、业务日期、拍摄方向和 ROI 元数据；
- 拍摄、上传、重启、弱网和锁定的端到端证据；
- 经业务审核的盘点数量金标；
- 商业产品分发或公开展示所需的数据许可。

## 生成和审查

执行 `scripts/build_test_dataset_manifest.py` 后，审查 `integrity_problems`、各 split 图像数和候选夹具的 `expected_pig_count`。记录输出的 `source_digest_sha256`，以便发现来源数据是否变化。

将任何真实推理基准集投入使用前，必须在受控存储中登记：数据来源、授权人、许可范围、采集日期、标注版本、审核人、ROI 规范、哈希清单和保留期限。该登记是 P1 `HttpYoloProvider` 的准入项。
