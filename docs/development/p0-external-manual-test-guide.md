# P0 外部人工验收与测试指导

**适用版本：当前 `main`；环境：仅 `pig-inventory-p0` 隔离 Compose 项目。**

本指南供未参与开发的测试人员执行。它补充而不替代 [`p0-manual-acceptance-runbook.md`](p0-manual-acceptance-runbook.md) 与 [`acceptance-criteria.md`](../product/acceptance-criteria.md)。只有 AC-01 至 AC-12 都有可复现证据，P0 才可进入现场试用。

## 1. 不可违反的测试边界

- 只可用本机生成的合成账号、栏舍、打印测试卡和照片；不得上传真实猪场照片、人员照片、生产账号、Token、`.env`、签名 URL 或模型权重。
- 不得运行 `docker compose down -v`，不得删除、重置或连接默认 `pig-inventory` MySQL 卷。
- 所有测试均使用 `pig-inventory-p0`；测试结束仅允许 `docker compose -p pig-inventory-p0 down`。
- 当前 Provider 为 `unavailable` 是预期安全降级：它必须返回 `review_required`、明确原因和**空数量**。任何模拟数量均为 P0 阻断缺陷。
- 左/中/右三图始终是一份 CaptureSet；在没有获验证多视角 Provider 时，任何简单相加数量均为 P0 阻断缺陷。
- 确认、普通删除、管理员覆盖删除和近重复解决都必须经后端审计；确认引用的媒体必须锁定。

## 2. 人员、设备和分工

| 角色 | 负责范围 | 账号 |
|---|---|---|
| 环境管理员 | 启动隔离环境、保管本机口令、收集非敏感日志 | bootstrap 管理员 |
| 现场操作员 | Android 采集、离线恢复、上传、任务查看 | `e2e-operator` |
| 复核员 | 确认、近重复解决、媒体复核 | `e2e-reviewer` |
| 猪场管理员 | 确认、审计浏览、带理由覆盖删除 | `e2e-farm-admin` |
| 隔离验证员 | 跨组织不可发现测试 | `e2e-second-operator` |

四个 `e2e-*` 账号由 Fixture 创建，口令仅存在测试机 `.env` 的 `APP_E2E_FIXTURE_PASSWORD`。环境管理员应通过受控本地方式提供口令；不得复制到聊天、截图、报告或 GitHub Issue。

最低设备：realme GT 7 Pro / Android 15、REDMI Note 14 5G（或 Android 14+、6GB/128GB 同级机）、Windows 测试机和 Chrome/Edge 最新稳定版。手机和测试机必须处在同一私有 LAN。

## 3. 环境启动与验收编号

在仓库根目录 PowerShell 执行。将端口替换为未被占用的端口；以下示例使用 8089。

```powershell
$env:GATEWAY_PORT = '8089'
docker compose -p pig-inventory-p0 up --build -d
.\scripts\ensure-lan-e2e-fixtures.ps1 -ComposeProjectName pig-inventory-p0
Invoke-WebRequest "http://localhost:$env:GATEWAY_PORT/actuator/health" -UseBasicParsing
```

健康检查必须返回 `UP`。Fixture 会创建：主组织 `E2E-B01 / E2E-P01 / E2E-P02`，第二组织 `E2E2-B01 / E2E2-P01`，以及第 2 节账号。脚本不会显示或提交口令。

为每次测试建立编号，例如 `P0-20260828-A`。记录：Git commit、Compose 项目、端口、开始/结束时间、操作者、设备/Android 版本、浏览器版本、APK SHA-256。报告只附状态截图、脱敏 HTTP 状态和时间，不附原图或秘密。

Android APK：

```powershell
.\scripts\build-lan-test-apk.ps1 -ApiBaseUrl "http://<测试机LAN-IP>:$env:GATEWAY_PORT" -Install
```

## 4. 通过、失败与证据规则

- **通过**：每一步的实际结果等于预期，且保留非敏感证据名称。
- **失败**：任一预期不符；记录后停止该 AC 的继续签署，不用手工改数据库或管理员绕过。
- **阻塞**：缺设备、环境不可用、授权未到位或外部决定缺失；不是“通过”。
- P0 阻断：泄露跨组织数据、显示伪造/自动三图数量、解锁确认媒体、无理由覆盖、未审计写操作、真实数据泄露。

截图命名：`<验收编号>-ACxx-步骤-设备-时间.png`。日志命名：`<验收编号>-ACxx-时间.log`。截图只含状态文字、时间、设备型号或 HTTP 状态码。

## 5. Android 验收步骤

### AC-01：离线草稿与三图恢复

1. 用 `e2e-operator` 登录，同步后确认仅见主组织栏舍。
2. 选择 `E2E-B01 / E2E-P01`，打开飞行模式，建立左/中/右采集组。
3. 拍左图后强制停止 App；重开后拍中、右图。
4. 检查栏舍、三方向、ROI、三张缩略图和原图预览均恢复；采集/队列页不得出现数量。
5. 保存为待上传。

**预期**：3/3 证据属于同一采集组，状态可恢复，数量为空。

### AC-02：弱网续传、后台和上传时令牌刷新

1. 联网重试上述包；确认第一个 Blob 成功后立即关闭 Wi-Fi 或开启飞行模式。
2. 检查队列未丢失且已成功资产不退回未上传；恢复网络后重试。
3. 最终应只传剩余 Blob，并显示“已提交，等待处理”。
4. 再创建一个包，锁屏/转后台后恢复网络；记录 WorkManager 自行开始上传的时间。
5. 让 Access Token 过期（由环境管理员按本地测试配置缩短 TTL 后执行），在上传过程中重试。

**预期**：原包、原幂等键、原本地媒体均保留；刷新 Token 后自动继续，不生成重复会话/媒体；刷新失败时变为“需要重新登录”，绝不删除媒体。

### AC-05：近重复

1. 对同一合成打印测试卡拍两张视觉相近、文件字节不同的 JPG/PNG；分别作为单图包提交。
2. 两图都必须保留；以 `e2e-reviewer` 打开管理端近重复列表，确认有汉明距离。
3. 带至少 8 个字符的理由解决告警；刷新后确认告警不再待处理，审计包含解决动作。
4. 上传明显不同的合成图片，确认不会把所有图片误报。

**预期**：近重复只提示，不自动删除/覆盖；解决不删除媒体且有审计。

### AC-06、AC-08、AC-09：安全降级、三图和确认锁定

1. 提交单图和三图包，打开各自复核页。
2. 核对状态为 `review_required`、有 Provider 不可用原因、数量为空；三图绝不能显示相加数量。
3. 让复核页的 Access Token 过期后刷新/确认，确认会自动 Refresh Token 并只提交一次。
4. 用 `e2e-reviewer` 输入 `11` 和至少 8 个字符原因确认。
5. 以普通删除尝试删除确认媒体，应得到冲突；以 `e2e-farm-admin` 填写原因覆盖删除。
6. 重新打开会话，确认删除是软删除状态，锁定和审计仍可见。

**预期**：确认锁定所有引用媒体；普通删除为 409；管理员覆盖有理由且产生 AuditEvent。

### AC-03、AC-04、AC-11：幂等、精确重复和角色隔离

1. 对同一待上传包连续点重试，或使用两台手机同时恢复网络；检查只得到一个包、会话、推理任务和每张媒体。
2. 在 `E2E-P01` 上传一张合成图片后，将**完全相同文件**提交到 `E2E-P02`。
3. 同组织必须拒绝精确重复；响应中不得泄露第一栏舍名称、路径或原图。
4. 用相同文件在第二组织提交；不得因第一组织而被阻断。
5. 分别登录四个账号验证：
   - OPERATOR：可采集、上传、查看本组织任务；不可确认、不可覆盖删除。
   - REVIEWER：可确认、可解决近重复；不可覆盖删除、不可读取审计。
   - FARM_ADMIN：可确认、查看审计、带理由覆盖删除。
   - 第二组织账号：猜测主组织 session/media UUID 时返回不可发现结果，不能读写。

## 6. 管理端验收

浏览器访问 `http://localhost:$env:GATEWAY_PORT`。使用无痕窗口重复以下检查。

1. 未登录时不得看到演示数量、任务、媒体或审计内容；登录后只访问同源 `/api/backend/...`。
2. 用 `e2e-reviewer` 打开任务会话：媒体预览应可见；DevTools 中不得出现 MinIO URL、Token URL 参数、localStorage/sessionStorage Token。
3. 网页确认：输入数量和理由，确认状态与 Android、数据库任务、日报一致；刷新后证据锁定状态仍存在。
4. 近重复：解决操作必须要求理由；成功后审计出现 `near_duplicate.resolved`，媒体不消失。
5. 报表：为同栏舍在三天确认 10、11、13，并保留一个待复核会话。日报/综合只计已确认项，原始均值为 `11.333...`，展示数量为 `11`，且有参与日期。
6. 审计：以 FARM_ADMIN 查看确认、普通删除/覆盖删除、近重复解决；逐项检查 actor、目标、理由、时间和相关 ID。
7. 键盘与可用性：Tab/Shift+Tab/Enter 能操作登录、刷新、任务和确认；焦点清晰。浏览器缩放至 130%，核心文本和按钮不截断。开启减少动态效果后不出现影响操作的动画。

## 7. AC-07、AC-12 专项

### AC-07 ROI

此项要求经授权的固定金标和获准 Provider。当前 `unavailable` Provider 只能验证 ROI 存储/边界，不能证明“检测框中心在 ROI 外不计数”。测试负责人必须标记为**阻塞**，直到有授权金标、获批模型及自动回归证据；不得用主观肉眼判断替代。

### AC-12 安全与运行

由部署负责人在非本地生产候选环境完成：TLS/HSTS/HTTP 重定向、明确 CORS 白名单、随机非默认密钥、私有 MinIO 匿名拒绝、日志秘密抽检、合成会话备份恢复、运行时许可证清单。不得上传任何生产配置或日志全文到公开仓库。
